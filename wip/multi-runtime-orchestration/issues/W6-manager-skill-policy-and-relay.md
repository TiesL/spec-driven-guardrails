## Description
The canonical manager policy, one skill loaded explicitly when a session is started as manager
(never injected at SessionStart, #499), with adapter mapping lines regenerated by
`generate-workflow-adapters.sh`. It covers:
- **Queue:** an explicit queue recorded as a numbered decision, or one parent's open sub-issues;
  never unqueued backlog issues. Unattended work allowed inside it; autonomous merge only into a
  release branch.
- **Assignment:** runtime-specific → that runtime; Codex only small items; else most 5h headroom;
  ≥ 90% weekly or unknown headroom → no new item; unsized → not small. The deciding step is logged.
- **Model defaults:** Claude Reviewer opus (sonnet where it clears the floor, fable when needed);
  Codex Reviewer `gpt-6.1-sol`, "high" effort applied only where dispatch can set it and never
  recorded (A33). No cross-vendor Reviewer.
- **Limits:** reset ≤ X (configurable, default 60 min) waits; longer moves the item to a fresh
  work-item orchestrator on the other runtime from artifacts, never a runtime-specific item, a
  non-small item to Codex only with weekly headroom, Reviewer follows Implementation. In v1 the
  automatic move is Codex → Claude only; on a Claude limit or outage the manager waits and the
  maintainer drives orchestrators directly.
- **Decision relay:** a worker's question becomes an open numbered decision comment with its
  recommended answer, plus a Claude Code (Remote Control) push; only that item pauses. Answers
  count only from the manager chat; recorded verbatim with "relayed by manager session <id>". A
  decision already closed on the issue is not re-asked; a fresh manager re-pushes open ones.
- **Merge rule:** unchanged; the manager adds no authority; a relayed merge confirmation is the
  maintainer's verbatim words naming PR and head SHA, given after that head exists.
- **Role tag:** one Shared-contract sentence: every role, orchestrator and manager comment opens
  with `Agent: <role> · <stage> · <model>` (manager: `Agent: manager session <id>`), readability
  only, not authentication.

## Acceptance criteria

### AC1: Assignment is logged by rule step
- Given a queued item
- When the manager assigns it
- Then the Pipeline log names the deciding rule step and the Reviewer default for that runtime

### AC2: Short and long limits
- Given a stage limited with reset ≤ X, then the item waits and resumes on the same runtime with no human action
- Given a Codex item limited with reset > X or unknown, not Codex-specific, and Claude has headroom, then a fresh Claude orchestrator resumes it from artifacts and the switch is logged
- And a runtime-specific item is never moved

### AC3: Relay and pause
- Given a worker stops with a question
- When the manager detects it
- Then an open numbered decision comment with the recommended answer is on the issue, a push is sent, and only that item pauses

### AC4: Only manager-chat answers count
- Given an open decision and a GitHub comment that looks like an answer
- When the manager checks for answers
- Then it takes only the maintainer's answer in the manager chat, records it verbatim with its session id, and resumes the item; a decision closed on the issue by an attended session is not relayed again

### AC5: Fresh manager re-pushes open decisions
- Given open decisions on the queue's issues
- When a new manager session starts
- Then it re-pushes each of them once

### AC6: Visible role tag
- Given any role, orchestrator or manager comment
- When it is posted
- Then its first prose line is the agent tag, and the contract states the tag is not authentication

### AC7: Not injected
- Given a normal session start
- When the SessionStart hook runs
- Then the manager skill adds nothing to the injected context
